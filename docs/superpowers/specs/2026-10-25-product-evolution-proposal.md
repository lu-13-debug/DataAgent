# 产品能力升级方案（待用户选择）

本文件是基于当前代码和接口的设计提案，尚未开始功能实现。保留上一轮全部未提交修改，不扩大到本次需求以外。

## 理解与现状

这次包含九组目标：新建向导、上传确认、执行监控、报告资产、命令面板、数据下钻、模型透明度、Windows 体验、模板与分享。它们共享数据与任务状态，宜按可独立验收的阶段实现。

已核对 `docs/api-contract.md`、`src/types.ts`、`src/api.ts`、`src/App.tsx`、NewAnalysis / DataPreview / Pages / RunPanel / ReportView / ModelSettings，以及 datasets / analytics / workflow / gateway / app / cloud-app 和 Electron 主进程与打包配置。

当前限制：

1. 数据集只公开标准列、清洗后的前 5 行和字符串 warnings。解析时源列名已丢弃，前端无法准确还原“标准字段 ← 源列名”；清洗后的样本也不能证明原文件空值率、类型或问题所在行。
2. 缺少某张业务表允许部分指标分析；已提供表缺少必填列、行缺必填值等会上传失败。应区分“不可计算的分支”和“不可接受的数据”，不把缺支付表一律作为全部分析的阻断条件。
3. 质量分目前只在实际报告中产生，规则为 100 减每项问题 5 分，最低 0；数据集卡片不能用 preview 或 warnings 长度冒充全量质量评分。
4. daily 没有跨日去重玩家集合；channels 是整份报告的渠道汇总。无法仅通过现有响应精确计算筛选期间 ARPPU、跨日去重付费人数或渠道联动后的每日活跃/留存。已有 AI 发现也不能伪装成对筛选子集重新生成的结论。
5. 当前没有任务摘要、事件流、单步重试/跳过/恢复、报告元数据、分享、归因统计和模型 usage 契约。网关目前使用 Chat Completions 调用，官方 Claude Messages 协议需在模型阶段核对并补齐，不能只加供应商品牌入口。
6. Electron 已实现单实例锁，保留并补充回归即可。主进程当前统一拒绝权限，通知需要限定可信服务来源的权限策略。安装包配置为未签名。

## 两条路线

### A：分阶段完成，允许兼容扩展接口（推荐）

既有字段、端点与额度行为保持兼容，新增可选元数据或新端点；旧数据没有新增信息时显示“历史数据未记录，请重新上传”，不猜测。所有新增服务能力同时支持 local/cloud，云端沿用账号隔离。涉及服务端的部分补测试、契约和部署说明。

分阶段验收后继续推进下一阶段，避免同时改动所有交互后无法定位回归。实际签名需要证书身份/凭据，公开发布需要服务器与发布环境；先把代码、测试和可审阅产物做完整。

### B：本轮只做现有契约允许的前端能力

实现向导、已知覆盖/缺表提示、上传进度与取消、样本预览统计、流程说明、按任务查询和重连状态、本机报告收藏/标签、保守对比、导出、命令面板及分析模板。

真实源字段映射、全量结构化质量/评分、真正轻量摘要/事件流、准确渠道时间联动、用量透传、跨设备报告元数据、云端分享及归因暂不实现；界面不给这些能力留下假入口。后台通知与可见性暂停的冲突必须明示：停止全部任务查询期间无法承诺即时得知服务器完成状态。

## 推荐 A 的阶段边界

| 阶段 | 交付内容 | 关键兼容边界 |
| --- | --- | --- |
| 1：数据到首份报告 | 三步向导加最终摘要确认、上传识别确认、字段映射/质量问题/覆盖范围、上传进度与取消、只读样本剖析、数据卡片引用和删除影响、五种分析模板 | 向 Dataset 添加可选识别/质量元数据，保留原字段；老客户端继续使用原响应。缺失元数据不推测，提供重新上传说明 |
| 2：任务与模型可控 | 批准前计划说明、失败原因和创建新任务式重跑、连接中断/恢复、摘要与事件流、去重通知、停止确认/额度释放、模型预设与错误诊断、非敏感档案、usage 透传 | 新摘要/事件端点与旧 GET task 并存；隐藏时停止常规轮询，后台通知使用受控事件流。重启恢复须重新获取当前会话 Key 并确认，不持久化凭据 |
| 3：报告复用与下钻 | 收藏/置顶/标签和筛选、两报告对比、基于此继续与来源链、CSV/PNG、证据联动与术语表、日期/渠道查询、上期对比、批注、表格视图、命令面板与快捷键帮助 | 新查询由服务端按原记录重新计算去重/比率；原报告保留原期间。批注不参与计算；筛选发现标注适用范围，不能复用全文结论冒充子集结论 |
| 4：Windows 成熟度 | 窗口状态/多屏可见性、托盘与关闭选项、通知聚焦、检查更新/校验/用户确认安装、单实例回归、反馈与安全诊断、签名评估与未签名说明 | 继续保持远程页面无 Node 权限、contextIsolation/sandbox、窄 IPC 来源校验；更新不能让任意远程 URL 执行程序 |
| 5：云端只读分享 | 有效期/撤销/隐藏收入、只读分享页、统计口径/品牌标识、访问与注册归因 | 仅 cloud 开放；独立撤销令牌，只返回脱敏后的报告，原始数据/账号/Key 不进入分享载荷；敏感指标连同相关摘要、发现与导出一起处理 |

“任务恢复”需区分客户端断线后的继续观察和服务重启后的恢复执行：前者不重复创建任务；后者不能恢复已经丢失的 Key 快照或自动重复收费模型调用。单步重试/跳过须由后端限制允许的状态、重算依赖、校验账本后开放，不能用前端按钮模拟。

## 第一阶段建议交互

向导为 **数据 → 问题 → 方式与成本** 三个输入步骤，最后独立显示 **摘要确认**，共四个画面；摘要确认不再要求重复填写。

- 数据：选择或上传，展示明确时间范围、原始/有效行数、业务表覆盖和缺表影响；上传完成先确认“自动识别”的只读字段映射。缺 payments 时明确“收入、ARPPU、付费人数不可计算”。
- 问题：目标与业务背景，标题随目标/期间生成，用户编辑后不再覆盖。时间、指标、对比对象的建议只提示，不以简单关键词拒绝创建。
- 方式与成本：对比协作/自动是否中途确认、实际是否启用 AI、产出形式；AI 独立开关，显示当前模型及发送内容类别。目标/背景可能由用户输入含个人标识，须提示不要粘贴原始玩家明细；软件不能承诺任意自由文本从未包含玩家信息。
- 摘要：展示数据、期间、缺表影响、标题、目标、模式、AI/模型、发送内容、20 额度及来源模板/报告。仅最后确认按钮创建任务。
- 底部固定文案：“本次冻结 20 额度；若启用 AI，模型费用由你的 API Key 承担”。失败或取消明确显示实际释放数额；不混淆服务额度和模型账单。
- 回退保留草稿；上次模式、数据集 ID、AI 意图按服务/runtime/账号隔离，仅保存非敏感选择。显式预填的模板/报告/重跑设置优先于记忆，已删除数据集和不可用 AI 自动纠正并说明原因。
- Enter 在可推进步骤下一步，Shift+Enter 换行；输入法组合输入不触发。最终摘要按 Enter 不应在焦点不明确时意外扣费；通过聚焦最终确认按钮执行。步骤标题接收焦点，保留 Modal 焦点陷阱。
- 上传进度区分“传输百分比”和“服务器识别中”，不伪造识别百分比。取消传输不等于撤销服务端已完成的上传，需处理响应竞态，防止误称已经删除。
- preview 按列搜索、类型与空值率明确注明“当前预览样本”，原文件质量使用服务端诊断。问题复制包含表/列/行号与修复建议，避免复制原始玩家 ID。
- Excel/飞书粘贴采用显式“粘贴表格”文本区，转换成 UTF-8 CSV 后沿用现有上传校验；只有完整验证制表符、引号、换行、大小和行数限制后才开放，不依赖读取系统剪贴板权限，不留半成品入口。

## 兼容、安全与风险

- 不删除旧字段或改写原任务记录。新增响应字段可选，旧数据按实际能力降级；新必填输入不施加到旧客户端。必要的服务端迁移采用版本化、可回滚结构，先备份再部署。
- 继续以 useAuth 判断运行模式；记忆、报告本机元数据与批注按 origin/runtime/userId 分区。Key 不进入 localStorage、数据库、日志、导出或诊断。
- 报告对比只有数据源、期间、币种、指标 ID/单位与口径能确认一致时才计算差值；其余并排展示并提示“不可直接比较”。
- 没有 usage 显示“供应商未返回用量”；费用需要用量和对应价格来源才估算，标注“估算”，不把配置价格当实际账单。连接测试诊断不回显供应商原始响应或凭据。
- 页面可见时断网 10 秒内显示状态需要请求超时和失败计时，不能只数失败次数；恢复后校准状态、终态通知去重，不自动重试收费创建。
- 事件流需账号认证、断线续传及去重；任务终态只触发一次 bootstrap 校准。SSE 不携带 Key，状态摘要不带报告全文和数据预览。
- 发布包 SHA256 可发现文件损坏，但与安装包来自同一被攻击来源的哈希不能独立证明发布者身份；签名与校验分别展示。
- 签名初步核查：微软 Artifact Signing Basic 官方列价 $9.99/月、5000 次签名，但公共信任证书的地区/身份受限，个人开发者目前限美国或加拿大；不能假定中国大陆主体可直接购买。传统 OV/EV 方案需按实际主体向供应商核价，不采购或生成假签名。

参考：[Electron 通知](https://www.electronjs.org/docs/latest/tutorial/notifications)、[微软签名方案与定价](https://azure.microsoft.com/en-us/products/artifact-signing)、[微软身份与地区要求](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart)。核查日期：2026-10-25。

## 验收方案

每阶段单独运行 npm test 与 npm run build，涉及接口的改动补 local/cloud 服务端契约与隔离测试，浏览器覆盖 390px、键盘、焦点、aria-live、减弱动画及打印。

重点验收包括：回退不丢输入、只在摘要提交一次收费请求、残缺数据对指标影响可见、源映射真实、样本统计不冒充全量、上传取消竞态、断网/恢复/终态去重、后台通知、不可比报告不算差值、筛选指标正确去重与成熟 cohort、分享收入脱敏及无原始数据入口、桌面通知权限/IPC 来源/更新哈希失败路径。

本次仅完成核对和提案，未运行新的测试或构建，未实施以上新功能。用户选择路线后，再把第一阶段细化为可执行设计与测试计划。

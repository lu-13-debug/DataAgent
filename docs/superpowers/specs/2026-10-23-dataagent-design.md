# DataAgent 首版设计

用户已在前序对话确认游戏运营分析、自带 Key 与服务额度，并明确要求立即在当前目录构建。

## 交互
桌面为侧边导航 + 分析工作区 + AI 动态侧栏。导航包含工作台、数据源、分析报告、Skill 库；底部额度与模型设置。移动端侧栏折叠，AI 动态以页签展开。浅色、细线条、低饱和绿色；所有界面中文。

初始打开真实计算的演示项目历史报告，标识示例数据。新建分析弹窗设置项目名、目标和运行模式，支持使用演示数据或上传 CSV/XLSX。协作模式在计划确认和报告生成前暂停；用户可追加业务背景。自动模式按限定 Skill 顺序运行。运行过程中可取消。

## 范围
本地单用户。登录/商用支付/组织权限不属于本次首版；试用额度独立账本可观察冻结、结算、释放。后续领域注册表目前 game 可运行，其他领域显示尚未开放。注册、活跃、支付三种标准数据类型；支持固定英文列与中文别名，不做任意 SQL 或上传代码执行。

## 数据与计算
标准表 users(user_id,registered_at,channel)、activity(user_id,event_time)、payments(order_id,user_id,paid_at,amount,currency,status)。项目可含 1-3 类表；仅据实际可用表生成对应分析。注册以 users 为准；缺失支付不编造收入。上传重复订单去重并记录警告；负数/无效时间/混合币种不静默合并。上传最大 20MB，解析后最大 200000 行。

DAU 按活跃事件逐日去重。付费率按当日活跃集合与成功支付集合交集计算。ARPDAU 为当日有效支付总额/DAU。ARPPU 为同口径有效支付额/去重付费人数。留存为按项目自然日、注册日 cohort 在第 N 天回访；窗口不成熟显示 null。报告包括覆盖范围、质量警告与证据指标。

## 架构
React/TypeScript/Vite 前端；Express API 与静态托管；SQLite 本地持久化。工作流为可持久化节点状态机，运行中节点经进程重启标记失败并释放额度，完成节点保留。API Key 仅存于进程内存。报告是 HTML 可打印 PDF，另有 Markdown 下载。

## 模型
兼容 chat/completions 的供应商接口；只发送脱敏指标与目标，不发送玩家标识。配置检查 URL、HTTPS（本地自托管允许 loopback HTTP）、模型与超时；凭据只发送指定供应商，无跨供应商自动重试。演示模式用确定性规则生成结论，明确显示本地分析，不冒充模型调用。自带 Key 模式失败会进入 failed 并释放额度，不静默降级。

## 验收
协作暂停和继续、自动完成、取消退款、重复结算幂等、成熟留存、付费去重、上传错误、API Key 不持久化；浏览器检查模式切换、对话追加、导航、报告导出、设置和移动布局。
